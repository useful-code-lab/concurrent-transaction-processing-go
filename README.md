# concur-platform (Asynchronous Concurrent Platform)

Высококонкурентная асинхронная платформа на Go. Проект реализует паттерн асинхронной обработки транзакций (CQRS) с использованием очередей брокера RabbitMQ и СУБД PostgreSQL. 

Архитектура позволяет полностью исключить состояние гонки (Race Condition) на уровне оперативной памяти приложения, делегируя упорядочивание хаотичных запросов пользователей персистентной очереди брокера и атомарным SQL-операциям.

---

## 🏗️ Архитектурные компоненты системы

1.  **API Gateway Сервер (`cmd/server`)**: Принимает WebSocket-соединения, изолирует пользователей по виртуальным комнатам ресурсов (`?id=...`), мгновенно сбрасывает задачи на обновление в RabbitMQ и вещает (broadcast) успешные события обратно клиентам.
2.  **Фоновый Воркер (`cmd/worker`)**: Однопоточный обработчик очередей. Читает задачи из RabbitMQ, выполняет атомарный `UPSERT` в PostgreSQL с проверкой оптимистической блокировки версий и отправляет отчет об успешной фиксации.
3.  **Симулятор Клиентов (`cmd/client`)**: Имитирует нагрузку от параллельных пользователей. Поддерживает постоянное WebSocket-соединение, реактивно обновляет экраны при внешней синхронизации и делает автоматический **Retry с экспоненциальной задержкой** при конфликтах.

## 🛠️ Инфраструктурная сборка и деплой (Minikube)

Перед развертыванием переключите контекст терминала на Docker-демон внутри кластера:

```bash
eval $(minikube docker-env) # Привязка к Minikube
```

### 1. Сборка Docker-образов компонентов
Используйте стадии мульти-сборки одного Dockerfile для компиляции независимых сервисов:
```bash
# Собираем API-сервер
docker build --target server -t concur-platform-server:v4 .

# Собираем фоновый воркер
docker build --target worker -t concur-platform-worker:v2 .

# Собираем клиентский симулятор нагрузки
docker build --target client -t concur-platform-client:v2 .
```

### 2. Запуск и применение манифестов
Разверните всю экосистему одной командой:
```bash
kubectl apply -f k8s-platform.yaml
```

### 3. Перезапуск подов для подтягивания нового кода
При обновлении локальных образов принудительно перезапустите деплойменты:
```bash
kubectl rollout restart deployment/platform-server-deployment
kubectl rollout restart deployment/platform-worker-deployment
kubectl rollout restart deployment/platform-client-deployment
```

## 🔍 Интерактивный тест изоляции комнат (wscat)

Поскольку платформа поддерживает динамическое распределение пользователей по изолированным комнатам ресурсов, проверьте работу независимого `ID 99`:

1. Пробросьте порт сервера:
   ```bash
   kubectl port-forward service/platform-server-service 8080:8080
   ```
2. Подключитесь консольным WebSocket-клиентом к новой комнате:
   ```bash
   wscat -c "ws://localhost:8080/ws?id=99"
   ```
3. Вы получите изолированное стартовое состояние, защищенное от фонового потока логов ресурса `ID 1`.
